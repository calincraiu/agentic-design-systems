# Chat talks. Code acts.

<div class="cols" markdown="1">
<div class="box" markdown="1">

### The Chat tab

- A conversation.
- Claude replies, and works only in **its own space**.
- Nothing on your computer changes.

</div>
<div class="box yours" markdown="1">

### The Code tab

- Claude works **inside one folder** that you choose.
- It can read and write the files there, and run tools.
- It **asks you first** before anything it hasn't been allowed to do.

</div>
</div>

> Demo, the same sentence in both tabs: **"Make a file called hello.md that says hello."** Where does the file end up?

<!-- notes -->
**The idea.** The Claude desktop app has two tabs that matter for this course.

In **Chat**, Claude writes back to you. It can also run small calculations or make a file for you to download, but always in its own space, away from your computer. It's like talking a design through with a colleague across a table: useful, but nothing on your desk changes.

In **Code**, you first open a *folder* on your computer. Claude can then read the files in it, create and change files, and run small programs (tools). Don't let the name put you off: "Code" doesn't mean *you* write code. It means Claude can act in your folder, not just talk.

**Why it matters.** In the demo, the same sentence gave two different results. Chat showed you the file's text, or a download. Code asked permission, and then the file was simply *there*, in your folder. The folder is the boundary: it's like handing a contractor the keys to one room. Those "Allow?" questions are called **permission prompts**. Read them: they tell you exactly what Claude is about to do.

**Try it yourself.** Once you have your own folder, ask the Code tab for a file, then open the folder in your file browser and find it.
