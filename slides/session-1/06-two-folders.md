# Two folders: the tutorial, and your project

<div data-widget="figure" data-name="folders" data-start="1"></div>

> Claude works inside a folder. So we keep the lesson and your work in separate ones.

<!-- notes -->
**The idea.** Claude Code works inside one folder: it reads the files there, and it creates and changes files there. That's why folders matter in this course. Think of an office with a pinned-up tutorial on one wall and your own project table in front of you.

- The **course folder** is the one you unzipped. It holds this app, the slides, the examples and the kits. It's the tutorial: you follow it, run it and read it, but you don't build your work in it.
- **Your own folder** starts empty today. It's your project. Your `CLAUDE.md`, your skills, the tools you take away and the tools you design all live there, and it's the folder you open in the Code tab when you want Claude to work for you.

A **kit** is a small set of files (a tool and a skill, for example) that you copy from the course folder into yours. That's how the tutorial hands you something to build on. Copying only goes in that direction.

**Why it matters.** If everything is mixed into one folder, you can't tell which files are the lesson and which are yours, and Claude can't either. Keeping them apart means your project stays clean and is easy to share, and the tutorial stays a reliable reference. If something you wrote seems to be missing, check which folder you were in.

**Try it yourself.** Look at the chip at the bottom right of every slide. It always says where you should be working: the Chat tab, the Code tab with your folder open, or this app.
